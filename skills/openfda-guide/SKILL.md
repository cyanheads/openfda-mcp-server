## Scope

openFDA's public API: drug, device, food, and cosmetic adverse-event reports, enforcement reports and device recalls, drug labels (SPL), the NDC directory and the NSDE package file, Drugs@FDA applications, Orange Book products with patents and exclusivities, Complete Response Letters, drug shortages, 510(k), PMA, and product classification records, veterinary events, and tobacco problem reports. Each record is an FDA submission or listing. The API returns no exposure data, so it cannot give rates, and openFDA's API disclaimer says to treat every result as unvalidated. Trial outcomes, pricing, and prescribing volume come from other sources.

## Identifiers

| Identifier | Shape | Yielded by | Consumed by |
|:--|:--|:--|:--|
| Product NDC | `69339-364`, hyphenated labeler-product | `openfda_lookup_ndc`, `openfda_drug_profile` identity (an original packager's label when one matches; `identity.is_original_packager: false` marks a repackager's), `openfda.product_ndc` on shortage and label records | `product_ndc:"…"` in `openfda_lookup_ndc` |
| Package NDC | `69339-364-05` | shortage records (one record per package), `packaging[].package_ndc` on NDC records | `packaging.package_ndc:"…"` in `openfda_lookup_ndc` |
| Package NDC, 11 digits | `00093171201` | claims data; `package_ndc11` on `openfda_lookup_ndc` with `dataset: "nsde"` | `package_ndc11:"…"` with `dataset: "nsde"` |
| Application number | `ANDA077861`, `NDA…`, `BLA…`; `NDA 210274` on a Complete Response Letter; `210274` on an Orange Book product | `openfda_search_drug_approvals`, `openfda_drug_profile` identity and approval, NDC records, `openfda.application_number` blocks | `application_number:"…"` in `openfda_search_drug_approvals` (`dataset: "drugsfda"` takes `NDA210274`, `crl` takes `NDA 210274`; `orangebook` takes `products.application_number:"210274"` with `products.application_type:"N"`, or `"A"` for an ANDA) |
| SPL set ID | UUID | label records, `openfda.spl_set_id` on NDC and shortage records, profile identity | `set_id:"…"` in `openfda_get_drug_label`; openFDA keeps one current label per set |
| K-number / PMA number | `K201189` / `P…` | `openfda_search_device_clearances`; `k_numbers` / `pma_numbers` on device recall records | `k_number:"…"` / `pma_number:"…"` in `openfda_search_device_clearances` |
| Product code | 3 letters, e.g. `OLO` | device recall, 510(k), PMA, and classification records | `product_code:"…"` on those endpoints; `openfda_search_device_clearances` with `pathway: "classification"` gives the device type's class and required submission |
| Recall number | `D-321-2016`, `Z-0050-2025` | enforcement records (`recall_number`); device recall records (`product_res_number`); `openfda_drug_profile` `recalls[].recall_number` | device enforcement `recall_number` equals device recall `product_res_number`; enforcement `event_id` equals device recall `res_event_number`; a drug recall's lots and distribution: `openfda_search_recalls` with `category: "drug"` and `recall_number:"…"` |
| `canvas_id` | 10 characters | any search tool with `stage: true` | `openfda_dataframe_describe`, `openfda_dataframe_query`, later `stage` calls |
| `next_cursor` | opaque token | any search tool, `openfda_lookup_ndc`, and `openfda_get_drug_label`, on a page read at `skip` 0 or by cursor | `cursor` on the same tool, with the same endpoint, `search`, and `sort` |

NDCs match only in their hyphenated form: `product_ndc:"69339364"` matches nothing. An 11-digit claims-style NDC has to be re-hyphenated first, or looked up as `package_ndc11:"<11 digits>"` with `openfda_lookup_ndc` `dataset: "nsde"`, which also holds packages whose listing has ended.

## Gates

**Query syntax**
- Separate terms with spaces. openFDA's documentation writes `+` for a space; the tools read a `+` that way where it separates clauses (`+AND+`, `+TO+`, `"a"+field:`), but inside a quoted phrase a `+` stays a literal plus: `reactionmeddrapt.exact:"INJECTION+SITE+PAIN"` matches nothing, `"INJECTION SITE PAIN"` matches 299,526.
- Write `AND`, `OR`, `NOT` in uppercase. With lowercase `and`, the same aspirin-and-serious search matches 13.8M reports instead of 435K.
- Quote every identifier value. openFDA splits an unquoted hyphenated value into its parts and ORs them, so `recall_number:D-321-2016` sent as written matches about 18,000 records (nearly all of drug enforcement) where the quoted form matches one. The tools send an unquoted term of letters and digits joined by hyphens quoted themselves, so a bare `D-321-2016` is safe there; a value holding any other character (`1.5-mg`, `D-0123*`) is sent as written, so quote it.
- A character openFDA refuses (``! # $ ; ? ^ ` | ~``, and anything outside printable ASCII) fails as `malformed_search` before any request, naming the character and its position: it is refused even inside quotes, so remove it or put a space in its place, write an accented letter as its plain letter (`e` for `é`: openFDA stores names unaccented, and the message names the letter), and write `NOT`, `OR`, or `*` where `!`, `|`, or `?` was meant.
- Before writing a date range, check the field's note in `openfda_describe_fields`. Most dates take `[20240101 TO 20241231]`. Shortage dates are stored `MM/DD/YYYY` and searched as `[2026-01-01 TO 2026-12-31]`; on `drug/shortages` the tools rewrite `YYYYMMDD`, `M/D/YYYY`, and `YYYY-M-D` to that form, in `openfda_count_values` too, but a raw unquoted date outside the tools misparses.
- `skip` stops at 25,000 (`pagination_limit_reached`). To read a larger match, start at `skip` 0 and pass each page's `next_cursor` as `cursor`, with the same endpoint, `search`, and `sort` (`limit`, `fields`, `include`, and `sections` may change); a cursor cannot come with `skip` above 0, `stage`, or `canvas_id`. Or narrow the search, for example by splitting a date range.

**Before concluding absence**
A zero or low count is not evidence until each of these has been ruled out:
1. **Empty or absent `openfda` blocks.** The harmonized `openfda.*` fields exist only where FDA could link the record to a product, and some datasets carry none: food, cosmetic, animal, and tobacco records, Orange Book products, Complete Response Letters, and NSDE rows have no block (drug adverse-event reports nest it under `patient.drug`, device ones under `device`; `device/classification` carries it). In drug enforcement, 2,934 of 18,110 records carry `openfda.generic_name`. 177,118 of 264,693 drug labels have no `openfda` block. In Drugs@FDA, `openfda.*` is on 12,526 of 29,452 applications, while `products.brand_name` is on 29,096. Repeat the search on the record's own fields: `product_description` for recalls, `spl_product_data_elements` for labels, `products.brand_name` for Drugs@FDA applications. For metformin, recalls go from 32 to 91 on `product_description`. For lisinopril, 567 labels with no `openfda.brand_name` turn up on `spl_product_data_elements`, beside 227 found by `openfda.brand_name`. (Figures as of 2026-11-10.)
2. **Name field and spelling.** In `drug/event`, `patient.drug.medicinalproduct` is the name as the reporter typed it. For atorvastatin, `medicinalproduct:"atorvastatin"` matches 343,931 reports, `medicinalproduct:"lipitor"` matches 180,918, and `patient.drug.openfda.generic_name:"atorvastatin"` matches 249,606. OR-ing all three matches 519,687. Pick one definition, state it, and use the same one for every drug you compare.
3. **Phrase vs `.exact`.** A quoted phrase on a text field matches the words anywhere in a value: `reactionmeddrapt:"liver injury"` also matches `DRUG-INDUCED LIVER INJURY` (58,268 reports). `reactionmeddrapt.exact:"LIVER INJURY"` matches only the whole term (23,867).
4. **Case on keyword fields.** Some fields are stored uppercase and match only in that case. `sponsor_name` is one, and the tool description says so. When a lowercase quoted value returns zero, retry it in uppercase.
5. **Section failures.** A section listed in `openfda_drug_profile`'s `degraded` is unknown, not empty.

**Before attributing or comparing**
- openFDA cannot tie two clauses to the same array element. `patient.drug.medicinalproduct:"aspirin" AND patient.drug.drugcharacterization:"1"` matches any report that names aspirin and has any suspect drug. In a 25-report sample, aspirin was concomitant in 24. To count only reports where the drug is the suspect, read `drugcharacterization` on each drug entry of the returned records, or on a staged slice in SQL. The same holds for every array of objects: `patient.drug` and `patient.reaction` on drug events; `device`, `patient`, and `mdr_text` on device events; `products` on food and cosmetic events and on Drugs@FDA applications, beside `submissions` and `products.active_ingredients`; `drug`, `drug.active_ingredients`, `reaction`, and `outcome` on animal events; `active_ingredients` and `packaging` on NDC records; `patents`, `exclusivity`, and `products.active_ingredients` on Orange Book products. A matched search or count that AND-s clauses under one such array carries a notice naming the array, the fields, and the staged SQL that requires one entry: stage the search with `stage: true` (a page read by cursor needs a call without `cursor`) and run that `WHERE` condition in `openfda_dataframe_query`. The notice stays silent when the clauses are OR-ed, when one array holds a single entry on every record (an Orange Book product's `products`), and on an empty result.
- `openfda_count_values` over an array field tallies every element of every matching report. Counting `reactionmeddrapt.exact` on reports that match `LIVER INJURY` also returns their co-reported FATIGUE, PAIN, and NAUSEA. Counting drug names under a drug search likewise lists the concomitant drugs.
- Report counts are not incidence. To compare two drugs, divide each drug's reaction count by that drug's total report count (`meta.total` from a search with `limit: 1`). Use the same name definition in both, and present the result as reporting proportions, not risk.
- `openfda_drug_profile` keys `adverse_events` on the typed name, as normalized (each run of whitespace and characters openFDA refuses read as one space), in `medicinalproduct`, ranks `approval` over the typed name's own Drugs@FDA matches, and keys recalls and shortage on `meta.fanOutKey`: the typed name when it is an ingredient of the resolved generic, otherwise that generic (brand input such as `Lipitor` keys on `ATORVASTATIN CALCIUM`). Each section names the product it describes. Compare `identity.application_number` with `approval.applicationNumber` before attributing the label to the approved product. Read `shortage.product` and `shortage.namesInput` before reading one presentation's status as the drug's: every `Humira` shortage record is a Hyrimoz or Simlandi one (as of 2026-11-10). Its recall search covers `openfda.generic_name` and `product_description`, so item 1's gap is closed for that one phrase, and `recalls_total` counts every match beside the newest 5 shown. A report that names the drug another way (a brand only, a misspelling) is still missed: use `openfda_search_recalls` for the complete list.
- Counting a date field (`receivedate`) returns the busiest dates first, not a time series; scope `search` to a date range of at most `limit` dates to get every bucket.

## Workflows

**Drug safety signal (drug X vs drug Y).** Run `openfda_drug_profile` per drug for orientation. Then fix one name definition per drug (item 2). Get each drug's total with `openfda_search_adverse_events` (`limit: 1`). Tally reactions with `openfda_count_values` (`patient.reaction.reactionmeddrapt.exact`, scoped to the drug). Choose the MedDRA terms that make up the concept from that tally, since "liver injury" covers several preferred terms. Report proportions with the caveats above.

**Device maker's recalls → clearances.** Search `openfda_search_recalls` with `category: device` and `endpoint: recall`, on `recalling_firm` plus `event_date_initiated:[20240101 TO 20241231]`. Each record's `k_numbers` / `pma_numbers` go to `openfda_search_device_clearances`, and `product_code` links to the device type. The hazard class (Class I/II/III) is only on device enforcement records: look them up with `recall_number:"<product_res_number>"` and `endpoint: enforcement`. A page read without `fields` leaves the lot lists out (`code_info`, plus `more_code_info` on enforcement records) and names them in `omitted_fields`; pass `include` to get them. A firm's name varies across divisions ("Medtronic Navigation, Inc.", "Medtronic Perfusion Systems"), so search the shared word.

**Shortage → products.** `openfda_search_drug_shortages` with `generic_name:"<ingredient>"` returns one record per package, with `status` on each. Pass `package_ndc` to `openfda_lookup_ndc` as `packaging.package_ndc:"…"`, or use `openfda.product_ndc` / `openfda.spl_set_id` to reach the NDC record and the label.

**Label question for a brand or generic.** One name matches many labels, from repackagers and multiple manufacturers (227 for `openfda.brand_name:"lisinopril"` as of 2026-11-10). To reach the original packager's label, add `AND openfda.is_original_packager:true` to the brand search (several labels or none can remain), or take `identity.spl_set_id` from `openfda_drug_profile` and search `set_id:"…"`. Otherwise narrow by `openfda.manufacturer_name`, `sort: effective_time:desc`, or a `set_id` you already hold. When the response returns an outline, re-call with `sections` naming only the sections that answer the question. For dosing in a population, that is usually `dosage_and_administration` plus the population section listed in the outline.

**Bulk analysis.** A search stages nothing unless it passes `stage: true`, or a `canvas_id` from an earlier staged call to add its table to that canvas; the response then carries `canvas_id` and `canvas_table`. Call `openfda_dataframe_describe` with the `canvas_id` for the staged table and column names before writing SQL, then `openfda_dataframe_query` with a read-only query. Pass the same `canvas_id` back to stage further results beside the first; the tables expire with the canvas.

A staged drain stops at about 16 MB. A drug adverse-event report runs tens of kilobytes, so the table holds a few hundred reports. Any `GROUP BY` over it describes only the staged slice, so compare `staged_rows` with `meta.total` before reading it as a population figure. For a distribution over everything that matched, use `openfda_count_values`. Stage when you need record-level logic that openFDA can't express, such as per-drug-entry suspect filtering.

A staged table holds every top-level field of the endpoint's records, with a fixed column set per endpoint (per category, dataset, or pathway), so two stagings of one endpoint share their columns. Scalars are text (`CAST` for math) and nested blocks are JSON columns. No staged adverse-event table has an `openfda` column: read the block as `json_extract(patient, '$.drug[N].openfda')` on drug events and `json_extract(device, '$[N].openfda')` on device events. A device report sends most fields on every record as `''` when unset, so test them with `= ''` or `NULLIF`, not `IS NULL`.
