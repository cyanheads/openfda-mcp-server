# 0.9.0 — 2026-10-25

## Added

- **`openfda-guide` agent skill** — a published skill under `skills/openfda-guide/` (with `references/query-syntax.md`) for agents calling the `openfda_*` tools: query-syntax gates that prevent silent zero results, checks before concluding a drug or device has no record, identifier joins across NDC, application number, SPL set ID, K-number, and recall records, and workflows for safety-signal comparison, device recalls, shortages, labels, and DataCanvas analysis. It ships in the npm package, the Docker image, and the `.mcpb` bundle, and the server serves it over MCP through `createApp({ skills })`: `skill://openfda-guide/SKILL.md` in `resources/list`, the `skill://{+path}` resource template, and the `io.modelcontextprotocol/skills` extension (`skills/list`). `tools/list` is unchanged.
- **Agent Plugins root manifests** — root `plugin.json` and `mcp.json` (Agent Plugins 1.0.0) beside the existing `.claude-plugin/` and `.codex-plugin/` manifests (mcp-ts-core 0.13.18, [cyanheads/mcp-ts-core#426](https://github.com/cyanheads/mcp-ts-core/issues/426)).
- **`add-skill` framework skill** — guidance for authoring a skill the server publishes in root `skills/`.
- **`start` and `test:coverage` scripts** — `bun run start` runs the built server; `bun run test:coverage` runs Vitest with coverage.

## Changed

- **Query echoes in `content[]` render as code spans** — the `Query:` line of search results shows the query as a code span (``Query: `recall_number:"D-0866-2026"` ``) instead of inline Markdown text, so it reads and copies exactly as sent. `structuredContent` is unchanged (mcp-ts-core 0.13.18, [cyanheads/mcp-ts-core#785](https://github.com/cyanheads/mcp-ts-core/issues/785)).
- **DataCanvas runs on DuckDB 2** — `@duckdb/node-api` ^1.5.6-r.2 → ^2.0.0-r.1, inside the peer range mcp-ts-core 0.13.17 added; the canvas SQL gate covers DuckDB 2 ([cyanheads/mcp-ts-core#778](https://github.com/cyanheads/mcp-ts-core/issues/778)).
- **Leaner `.mcpb` bundle** — the bundle cleaner strips the framework's build-only files (its `CLAUDE.md`, `changelog/`, `scripts/`, `templates/`) (mcp-ts-core 0.13.18, [cyanheads/mcp-ts-core#791](https://github.com/cyanheads/mcp-ts-core/issues/791)), and `.mcpbignore` root-anchors the repo-local paths, `/data/` included, so a local mirror database never enters the bundle.
- **Docker image** carries `skills/` into the production stage.
- **Framework skills and scripts** resynced to mcp-ts-core 0.13.18: `check-skills-sync.ts`, `clean-mcpb.ts`, `devcheck.ts`, and `lint-packaging.ts`, plus the updated `framework-skills/`.
- **Bug report form** gains an Environment table.
- **CONTRIBUTING and SECURITY** — CONTRIBUTING drops the pull-request line and accepts plain issues; SECURITY asks reporters to redact API keys and credentials.
- **README** shortens Getting started to the hosted instance, the local `npx` install, and a generic client config.
- **`.env.example`** documents `LOG_LLM_INTERACTIONS`.
- **`minimumReleaseAge`** in `bunfig.toml` drops from 3 days to 1 day.

## Fixed

- **HTTP memory growth under sustained traffic** — 0.8.2 ran on mcp-ts-core 0.13.16, whose HTTP transport retained about 71 KiB per request through its shutdown signal, so a long-running HTTP server's heap grew until the process ran out of memory. mcp-ts-core 0.13.17 gives each exchange its own `AbortController`, released when its response ends ([cyanheads/mcp-ts-core#786](https://github.com/cyanheads/mcp-ts-core/issues/786)).
