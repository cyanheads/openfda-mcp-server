# 0.9.1 — 2026-10-26

## Changed

- **Adverse-event text output decodes route, outcome, and age-group codes** as `label (code)` (`via oral (048)`, `fatal (5)`, `elderly (6)`) ([#72](https://github.com/cyanheads/openfda-mcp-server/issues/72)). `structuredContent` keeps the raw codes, and the `openfda_describe_fields` notes read from the same table.

## Fixed

- **`search` is sent to openFDA in one pair of parentheses** ([#84](https://github.com/cyanheads/openfda-mcp-server/issues/84)). A top-level `OR` on drug, food, and device enforcement matched only the last clause (food `cheese OR milk`: 1,675 → 3,141).
- **A URL-style `+` in `search` reads as a space** where it separates: beside `AND`/`OR`/`NOT`/`TO`, after a closing `"` `)` `]` `}`, or before a `field:` prefix ([#75](https://github.com/cyanheads/openfda-mcp-server/issues/75)). A `+` inside a quoted phrase stays literal, and a zero-result hint names the phrase. Applies to ten tools; a query using Lucene's required `+` keeps its last two positions literal.
- **`openfda_count_values` on a date field** maps openFDA's `time` buckets to `term`, ranks them by count (ties by date), and truncates exactly; unreadable rows are dropped and disclosed ([#78](https://github.com/cyanheads/openfda-mcp-server/issues/78)).
- **`openfda_drug_profile` fan-out key** is the typed term when its words appear whole in the resolved generic name, so one label's product-specific generic no longer narrows recalls, approval, and shortage ([#82](https://github.com/cyanheads/openfda-mcp-server/issues/82)).
- **`openfda_drug_profile` recalls and approval** also search `product_description` and `products.active_ingredients.name`, and the new nullable `recalls_total` counts every recall match beside the newest 5 (`## Recalls (5 of 91)`); an empty recalls or approval section names the fields it searched ([#79](https://github.com/cyanheads/openfda-mcp-server/issues/79)).
- **`openfda_drug_profile` `content[]`** reads "Unknown — the … search failed upstream (see Degraded)." for a label, adverse-event, recall, approval, or shortage section whose sub-query failed; the absent wording prints only when the search succeeded and matched nothing ([#86](https://github.com/cyanheads/openfda-mcp-server/issues/86)).
- **Caller text in notices and `format()` prose** renders as a code literal on both surfaces, so wildcards and underscores read back as sent ([#81](https://github.com/cyanheads/openfda-mcp-server/issues/81)).
- **`openfda_get_drug_label` `set_id` description** and the catalog note say a `set_id` returns the current revision only ([#80](https://github.com/cyanheads/openfda-mcp-server/issues/80)).
