# 0.11.0 — 2026-11-22

## Added

- **`openfda_search_drug_approvals` reads the Orange Book and Complete Response Letters** through a new `dataset` input: `orangebook` (`drug/orangebook`: each product's patents, exclusivities, and therapeutic-equivalence codes) and `crl` (`transparency/crl`: the letter's text, fenced in `content[]`), beside the default `drugsfda`. A call with neither `search` nor `sort` returns newest first by `approval_date` or `letter_date`; `limit` defaults to 25 (cap 1000) on the Orange Book and 5 (cap 75) on letters ([#93](https://github.com/cyanheads/openfda-mcp-server/issues/93)).
- **`openfda_lookup_ndc` resolves 11-digit and discontinued NDCs** with `dataset: "nsde"` (`other/nsde`): `package_ndc11`, marketing start and end dates, and the billing unit. An empty `drug/ndc` lookup of an NDC-shaped value names the hyphenated spellings to try and the NSDE call ([#94](https://github.com/cyanheads/openfda-mcp-server/issues/94)).
- **`openfda_search_adverse_events` takes `category: "cosmetic"`** (`cosmetic/event`), newest first by `initial_received_date`, `limit` 25 (cap 1000) ([#95](https://github.com/cyanheads/openfda-mcp-server/issues/95)).
- **`openfda_search_device_clearances` takes `pathway: "classification"`** (`device/classification`): a product code's device class, regulation number, and submission type, labeled beside the raw code in `content[]` (`Class II (2) | 510(k) (1)`). The pathway has no default sort, since openFDA sorts it only on `device_name.exact` and `regulation_number.exact`; `limit` 25 (cap 600) ([#96](https://github.com/cyanheads/openfda-mcp-server/issues/96)).
- **`cursor` and `next_cursor` on the nine paging tools** (adverse events, recalls, drug approvals, device clearances, animal events, drug shortages, tobacco reports, NDC, and drug labels): a page read at `skip` 0 or by `cursor` returns `next_cursor` while records remain, and following it reads past openFDA's 25,000-record `skip` ceiling. A cursor is bound to its endpoint, `search`, and `sort`; with any other, or with `skip` above 0, `stage`, or `canvas_id`, the call fails as `invalid_cursor`. `limit`, `fields`, and `include` may change between pages ([#97](https://github.com/cyanheads/openfda-mcp-server/issues/97)).
- **`include` and `omitted_fields`** on `openfda_search_adverse_events` and `openfda_search_recalls`: a page that leaves a path out lists it with its byte size in `omitted_fields`, and `include` returns it, whole or one field beneath it ([#104](https://github.com/cyanheads/openfda-mcp-server/issues/104)).
- **`openfda_drug_profile` output** gains `approval.approvalDate`, `approval.reviewPriority`, and `approval.submissionClass` (from the earliest approved original submission, never a supplement), and `recall_number` and `status` on each `recalls[]` entry ([#106](https://github.com/cyanheads/openfda-mcp-server/issues/106)).
- **A drug-label outline page names its labels** in `page_labels`: `set_id`, `effective_time`, `brand_name`, `generic_name`, `manufacturer_name`, `is_original_packager`, and `bytes` per label ([#107](https://github.com/cyanheads/openfda-mcp-server/issues/107)).
- **`openfda_count_values` and `openfda_describe_fields` cover 24 endpoints**, adding `drug/orangebook`, `transparency/crl`, `other/nsde`, and `cosmetic/event` ([#93](https://github.com/cyanheads/openfda-mcp-server/issues/93), [#94](https://github.com/cyanheads/openfda-mcp-server/issues/94), [#95](https://github.com/cyanheads/openfda-mcp-server/issues/95)).

## Changed

- **Breaking: default pages leave their heaviest fields out.** `openfda_search_adverse_events` with `category: "drug"` no longer returns `patient.drug[].openfda`; `openfda_search_recalls` no longer returns `code_info` and `more_code_info` on device enforcement, or `code_info`, `openfda.k_number`, `openfda.fei_number`, and `openfda.registration_number` on device recall. `include`, `fields`, or a `search` clause naming the path returns it. At each endpoint's `limit` cap, a page of 25 drug reports is 101,700 bytes against 554,184 with every path included, 125 device enforcement reports 176,579 against 2,522,664, and 50 device recalls 158,238 against 2,507,883 ([#104](https://github.com/cyanheads/openfda-mcp-server/issues/104)).
- **Breaking: staged tables drop the columns no record filled.** `openfda` on the drug and device adverse-event tables; `pma_number`, `supplement_number`, `trade_name`, and `generic_name` on the 510(k) table; `k_number`, `device_name`, `decision_description`, `clearance_type`, and `country_code` on the PMA table. `openfda_dataframe_query` SQL naming one fails as `invalid_query`; 0.10.0 answered NULL in every row ([#105](https://github.com/cyanheads/openfda-mcp-server/issues/105)).
- **Staged tables carry every top-level upstream field** on the adverse-event, device-clearance, animal-event, drug-shortage, and NDC tools, in a fixed column list per endpoint: drug adverse events 11 → 27 columns, device adverse events 10 → 90, 510(k) 19 → 24, PMA 19 → 24, animal events 12 → 20, NDC 16 → 22, drug shortages 14 → 19 ([#105](https://github.com/cyanheads/openfda-mcp-server/issues/105)).
- **`openfda_search_drug_shortages` returns newest first** by `update_date` when `search` and `sort` are both omitted, inline and staged ([#108](https://github.com/cyanheads/openfda-mcp-server/issues/108)).
- **`tools/list` is smaller with five datasets added**: 117,793 bytes against 135,792 on 0.10.0. A rule several tools share is stated once in a short clause, and the descriptions in the listing fall from 86,126 to 64,618 bytes. The trim rewrites descriptions only ([#109](https://github.com/cyanheads/openfda-mcp-server/issues/109)).
- **Descriptions say an unsorted match comes in openFDA's index order**, where they said relevance order ([#109](https://github.com/cyanheads/openfda-mcp-server/issues/109)).
- **The advertised `limit` maximum rises** to 1000 on `openfda_search_drug_approvals` (from 375) and 600 on `openfda_search_device_clearances` (from 575), each tool's largest per-dataset cap. With `OPENFDA_CLAMP_LIMITS=false`, a `limit` between a dataset's cap and that maximum fails as `limit_above_cap` where it failed argument validation.
- **Empty-page lines name no single dataset**: `No drug application records found.` and `No device records found.` on every dataset or pathway of those two tools.
- **Server `instructions` name every dataset the tools reach**: cosmetics, tobacco, the Orange Book, Complete Response Letters, drug shortages, and device classifications join the list, and the sentence on the `openfda` block names each record type that carries none.
- **The `openfda-guide` skill (1.1 → 1.2)** covers the new datasets, `cursor`, `include`, and the search normalization.

## Fixed

- **`openfda_drug_profile` reads a drug name holding a character openFDA refuses.** `acetaminophen; codeine` returns the profile of `acetaminophen codeine` (8,032 adverse-event reports) and `Ozempic®` that of `Ozempic`, where every section failed as `query_error`. A name with no ASCII letter or digit (`*`, `-`, `®`) raises `blank_drug_name` before any request, where `*` profiled an unrelated drug. An accented letter reads as its plain letter, the spelling openFDA stores: `Néoral` returns the profile of Neoral. `meta.fanOutKey` shows the name as searched ([#98](https://github.com/cyanheads/openfda-mcp-server/issues/98)).
- **AND-ed clauses on one array path carry a notice.** openFDA tests each clause against the whole record, so `patient.drug.medicinalproduct:"X" AND patient.drug.drugcharacterization:1` can be met by two different drugs. The notice names the array, the fields, and the staged SQL that requires one entry to meet them together; it appears on the search tools of eight endpoints and on `openfda_count_values`, which names the tool to stage with ([#100](https://github.com/cyanheads/openfda-mcp-server/issues/100)).
- **An unquoted hyphenated value is sent as a phrase.** openFDA split it and matched records holding any part: `recall_number:D-0123-2024` matched 18,148 recalls and now matches 1, `0003-0894` on the NDC directory 259 and now 1, `product_description:extended-release` 605 and now 427. Ranges, wildcards, and quoted values are sent as written, and the echoed query shows the quoting ([#101](https://github.com/cyanheads/openfda-mcp-server/issues/101)).
- **`openfda_search_drug_shortages` reads calendar dates in three forms** on `initial_posting_date`, `update_date`, `discontinued_date`, and `change_date`: `YYYYMMDD`, `M/D/YYYY`, and `YYYY-M-D` are rewritten to `YYYY-MM-DD`, as terms and as range bounds, and `openfda_count_values` does the same on `drug/shortages`. `initial_posting_date:20211215` matched nothing and now matches 22 records; an unquoted `initial_posting_date:12/15/2021` matched 84 unrelated records and now those 22; `initial_posting_date:[20211201 TO *]` matched all 1,581 records and now 992. A `field:(…)` group on one of those fields is sent as written, and a search or count that matches nothing under one says to write each date in it `YYYY-MM-DD` ([#102](https://github.com/cyanheads/openfda-mcp-server/issues/102)).
- **A character openFDA refuses fails as `malformed_search` before any request**: `` ! # $ ; ? ^ ` | ~ ``, an ASCII control, or a character outside ASCII. The error names the character and its position and says what to write instead (`*` for `?`, `NOT` for `!`, `OR` for `|`, the plain letter for an accented one). 0.10.0 sent the query and returned openFDA's HTTP 400 as `query_error` with the query HTML-escaped. A tab, line break, or non-breaking space between clauses now reads as a space ([#103](https://github.com/cyanheads/openfda-mcp-server/issues/103)).
- **An openFDA error message is decoded once**: `&quot;` in the echoed query reads as `"` ([#103](https://github.com/cyanheads/openfda-mcp-server/issues/103)).
- **A query openFDA refuses that holds `25000` is a `query_error`**; it was reported as `pagination_limit_reached`.
- **An openFDA error body whose `message` or `details` is not a string** is shown as sent; it rendered as `[object Object]`.
- **`openfda_search_animal_events` masked-name guidance** appears only when the search filters on `drug.brand_name` or `drug.manufacturer.name` as a field; it also fired when the name sat inside a quoted phrase or a longer path.
- **A drug shortage record's `therapeutic_category` list** renders with a space after each comma.
- **The drug-label next-page line at `skip` 25,000** names `next_cursor`; it suggested `skip=25001`, which openFDA refuses ([#97](https://github.com/cyanheads/openfda-mcp-server/issues/97)).
- **A drug-label outline's re-call guidance names every input that chose the page**: `search`, then `sort`, a `limit` other than 5, a `skip` above 0, and `cursor`, as the call set them (`Re-call with the same search, limit, and skip plus sections:[...]`). It named only `search`, so following it from a page read at another `limit` or `skip` returned different labels.
- **The `openfda_search_recalls` no-match hint on device recalls** names `openfda.device_class`; it named `classification`, a field `device/recall` records do not carry.
