# 0.4.3 — 2026-07-26

## Changed

- **`bunfig.toml`** — `install.security.scanner` wired to `@socketsecurity/bun-security-scanner` (pre-install malware/typosquat/CVE scan).
- **`.gitignore`** — anchors `data/` to `/data/` (repo root only) and adds `.tmp/` (DuckDB spill directory).
- **Dockerfile** — OTEL install stage adds `--omit=dev --ignore-scripts`.
- **`.env.example`** — documents `MCP_LOG_RATE_LIMIT_THRESHOLD` / `MCP_LOG_RATE_LIMIT_WINDOW_MS`.
- **`scripts/check-dependency-specifiers.ts`** — extends the floating-specifier check to `package.json`'s `overrides` section.
- **`scripts/clean-mcpb.ts` / `scripts/lint-packaging.ts`** — strip and verify platform-specific `@duckdb/node-bindings-*` entries from the `.mcpb` bundle alongside the existing agent-doc strip, so the bundle stays cross-platform and under the 25 MB registry cap.
- **`scripts/devcheck.ts`** — outdated-dependency check exempts peer-range rows and simplifies the release-age-hold logic.
- `scripts/`, `skills/` resynced from the `mcp-ts-core` template.

## Fixed

- **`OpenFdaService.query`** — passes `expectedStatuses: [404]` to `fetchWithTimeout` so a handled openFDA no-match 404 logs at `debug` instead of `error`; the tool response is unchanged. ([#22](https://github.com/cyanheads/openfda-mcp-server/issues/22))
- **`OPENFDA_QUERY_ERROR_5XX`** — gains `parse_exception`, so unbalanced brackets/parens, a dangling `AND`/`OR`, and malformed range syntax classify as non-retryable `query_error` instead of retrying 4x as `upstream_error`. ([#33](https://github.com/cyanheads/openfda-mcp-server/issues/33))
- **`openfda_count_values`** — a `Nothing to count` 404 now raises a distinct `not_aggregatable` error naming the offending expression and, for a `.exact` suffix on an already-keyword field, the bare-field correction; a genuine `No matches found!` 404 keeps the existing empty-result behavior. `describe_fields` `queryTips` stops presenting `.exact` as the default for string fields. ([#34](https://github.com/cyanheads/openfda-mcp-server/issues/34))
- **Blank free-text inputs** — every required and optional free-text input (`search`, `sort`, `canvas_id`, `count`, `query`, `drug`) now rejects `""` and whitespace-only values at the schema layer via the new `nonBlankString()` helper, before any upstream request; omitting an optional field still browses. Previously the URL builder dropped the falsy value and openFDA read it as match-all, turning a targeted lookup into an unfiltered browse of the whole endpoint. ([#25](https://github.com/cyanheads/openfda-mcp-server/issues/25), [#35](https://github.com/cyanheads/openfda-mcp-server/issues/35))
- **`openfda_drug_profile`** — `Unauthorized`, `Forbidden`, `ConfigurationError`, and a cancelled fetch now propagate to the caller instead of collapsing into an empty best-effort profile; a global failure during identity resolution short-circuits before the five-way sub-query fan-out. Per-section failures (rate limits, a 5xx on one endpoint, a rejected query) still degrade gracefully, and the output now carries a `degraded[]` array naming the failed sections and reasons, rendered as a `## Degraded` block ahead of the profile sections. A drug name that sanitizes to nothing after quote-stripping (e.g. `"""`) throws a declared `blank_drug_name` error before touching openFDA. ([#26](https://github.com/cyanheads/openfda-mcp-server/issues/26), [#25](https://github.com/cyanheads/openfda-mcp-server/issues/25))
