# 0.10.0 — 2026-11-10

## Added

- **`OPENFDA_CLAMP_LIMITS`** (default `true`) controls what a `limit` above its endpoint's cap does: `false` rejects it instead of clamping — at the schema `maximum` above the tool's largest cap, as `limit_above_cap` between the endpoint's cap and that maximum ([#92](https://github.com/cyanheads/openfda-mcp-server/issues/92)).
- **A `limit` above the endpoint cap returns the cap's worth of records** with a notice on both surfaces naming the requested value, the cap, and the next `skip`, plus one log line and an `openfda.limit.clamped` counter increment; `openfda_count_values` and `openfda_get_drug_label` clamp at 1000 ([#92](https://github.com/cyanheads/openfda-mcp-server/issues/92)).
- **`openfda_drug_profile` output** gains `identity.manufacturer`, `identity.application_number`, and `identity.is_original_packager`; `approval.brandNames` and `approval.candidates`; and `shortage.product`, `company`, `presentation`, `namesInput`, `total`, and `statusCounts` ([#85](https://github.com/cyanheads/openfda-mcp-server/issues/85)).
- **`openfda_describe_fields`** lists `spl_product_data_elements` on drug labels ([#89](https://github.com/cyanheads/openfda-mcp-server/issues/89)), `event_date_initiated` (the default sort) on device recalls ([#88](https://github.com/cyanheads/openfda-mcp-server/issues/88)), and eleven coded drug adverse-event fields with their code lists ([#90](https://github.com/cyanheads/openfda-mcp-server/issues/90)).
- **Adverse-event reports label FDA's categorical code fields** beside the raw value: onset-age unit, drug action, dechallenge, rechallenge, treatment-duration, dosage-interval, and dose units, report type, reporter qualification, sender and receiver type, and the expedited flag (`3 month (802)`); codes FDA's field reference leaves undefined stay raw ([#90](https://github.com/cyanheads/openfda-mcp-server/issues/90)).

## Changed

- **Breaking: `openfda_dataframe_query` refuses a query that names a column alias, table alias, or CTE after a DuckDB system view** (`pg_class`, `duckdb_tables`, `sqlite_schema`, `pg_tables`, `pg_settings`); 0.9.1 answered those. The refusal names the alias or CTE to rename.
- **Breaking: `page_omitted` is removed from all eight search tools' output**, and no page is cut at 24,000 bytes: a page carries the `limit` records asked for, up to the endpoint's cap ([#92](https://github.com/cyanheads/openfda-mcp-server/issues/92)).
- **`limit` defaults are per endpoint**: 5 for drug adverse events and labels; 10 for device adverse events, device enforcement, device recalls, and 510(k); 25 for the rest; 100 for `openfda_count_values`. Caps run from 25 (drug adverse events) to 1000 ([#92](https://github.com/cyanheads/openfda-mcp-server/issues/92)).
- **`page_bytes` and `page_largest_fields`** appear only when a record on the page exceeds 24,000 bytes; a `fields` projection no longer lifts a page past the endpoint's cap ([#92](https://github.com/cyanheads/openfda-mcp-server/issues/92)).
- **A call with neither `search` nor `sort` returns newest first** on the adverse-event, recall, device-clearance, animal-event, tobacco, and approvals search tools, sorted on each endpoint's date field, inline and staged; an explicit `sort` is sent as given, and a call with a `search` and no `sort` is unchanged. Drugs@FDA sorts by latest submission, not approval date ([#88](https://github.com/cyanheads/openfda-mcp-server/issues/88)).
- **`openfda_drug_profile` picks the drug's own product**: `approval` is ranked over up to 100 Drugs@FDA applications; `identity` and `label` come from that application's original-packager label, else an original packager's label matching the name, else any matching label, then the NDC directory; `shortage` shows the brand input's own record first with the match total. Each section names its product ([#85](https://github.com/cyanheads/openfda-mcp-server/issues/85)).
- **`openfda_drug_profile` shares one 50-second budget across every request it chains**; a request the budget cuts lands in `degraded` with reason `timeout` ([#85](https://github.com/cyanheads/openfda-mcp-server/issues/85)).
- **Every openFDA query settles under one 50-second deadline across its retries.** A retry sequence that would run past it fails with `Timeout` (`retry_deadline_exceeded`) instead of finishing late, and a request the deadline leaves no time for is never sent.
- **A fractional `limit` fails argument validation** before any request; openFDA answers one with HTTP 400.
- **Product-name hints name each endpoint's own field**: adverse-event empty results point at `patient.drug.medicinalproduct`, `patient.drug.openfda.brand_name`, `device.brand_name`, or `products.name_brand`; approvals lead with `products.brand_name`, which joins the `drug/drugsfda` field catalog; the label notice names `spl_product_data_elements`; the server instructions say where the `openfda` block exists ([#89](https://github.com/cyanheads/openfda-mcp-server/issues/89)).
- **The approvals no-match hint and the `sponsor_name` catalog note** say the value is stored uppercase.
- **A truncated staging notice names what stopped it**: openFDA's 25,000-row ceiling or the size budget.
- **A `rate_limited` error carries openFDA's `Retry-After` as `retryAfter`**, and the retry ladder honors it.
- **Framework skills, scripts, and `changelog/template.md`** synced to mcp-ts-core 0.13.22.

## Fixed

- **`openfda_search_adverse_events` `content[]` pairs each reaction with its outcome** (`Death — fatal (5)`), renders the MedDRA version once when every reaction shares it, and shows onset age with its unit; the patient and report fields no longer render inside the last drug's list item ([#90](https://github.com/cyanheads/openfda-mcp-server/issues/90)).
- **List endings** in the adverse-event, approvals, animal-event, tobacco, and NDC renderers: a blank line ends each list, so the next block no longer continues the last item.
- **An approvals heading** falls back to the application's `products[]` brand name when openFDA harmonized no `openfda` block.
- **The `openfda_lookup_ndc` example search** uses `labeler_name`.
- **An unexpected openFDA status** carries openFDA's own error detail in the message, and an HTML error page from the proxy in front of openFDA contributes only its title.
- **The scheduled mirror refresh stops before the stores close at shutdown**, skips a store another process holds, and the mirror CLI initializes its logger.
- **The `openfda-guide` skill (1.0 → 1.1)**: the bulk-analysis workflow says a search stages only with `stage: true` or a `canvas_id` and no longer overstates drug adverse-event report size ([#91](https://github.com/cyanheads/openfda-mcp-server/issues/91)); the absence gate adds Drugs@FDA's `products.brand_name` ([#89](https://github.com/cyanheads/openfda-mcp-server/issues/89)); the `openfda_drug_profile` notes cover its product selection ([#85](https://github.com/cyanheads/openfda-mcp-server/issues/85)).
