# 0.8.0 — 2026-10-03

## Added

- `openfda_dataframe_drop` deletes one table or view from a staged DataCanvas. It is off unless `OPENFDA_DATAFRAME_DROP_ENABLED=true`; while off it stays listed as a disabled tool, not callable. It needs `CANVAS_PROVIDER_TYPE=duckdb`. For an expired or unknown `canvas_id` it reports `canvas_not_found` with the hint that no drop is needed ([#70](https://github.com/cyanheads/openfda-mcp-server/issues/70)).
- `CANVAS_PROVIDER_TYPE` is newly listed in `server.json` (both npm entries) and the `manifest.json` user config, alongside `OPENFDA_DATAFRAME_DROP_ENABLED`, so registry and bundle installs can see how to turn staging on. It was already in the README.
- **`.env.example`** lists the DataCanvas (`CANVAS_PROVIDER_TYPE`, `OPENFDA_DATAFRAME_DROP_ENABLED`) and local bulk mirror variables, plus the framework's `MCP_REQUEST_STATE_KEY`, `LOG_TOOL_FAILURE_PAYLOADS`, and per-signal `OTEL_EXPORTER_OTLP_*_ENDPOINT` overrides.

## Changed

- `@cyanheads/mcp-ts-core` ^0.13.6 → ^0.13.11: tool errors end with `request <id>` and carry `data.requestId` (0.13.10), and error data no longer includes server stack traces (0.13.7) or request context (0.13.8); an integer sent for a string field and a JSON-stringified object are repaired before validation, and argument rejections name the alias rewrites behind them (0.13.9); `ctx.log` notifications to the client honor `MCP_LOG_LEVEL` and mask sensitive fields (0.13.11); MCP SDK ^2.2.0 (0.13.9, 0.13.11). Framework refs are cyanheads/mcp-ts-core releases.
- **Output-schema violations** — a tool result that breaks its output schema now fails as `-32603` (0.13.8).
- **HTTP transport** — a protocol revision 2026-07-28 POST without `MCP-Protocol-Version` is refused with 400/-32020, and a JSON-RPC batch over 100 messages is refused with 400/-32600 (0.13.9).
- **Canvas scratch files** live in a private per-process directory, and `CANVAS_TEMP_PATH` now names its parent (0.13.9).
- **Declared recovery hints** reach the wire through the framework's fill rather than `ctx.recoveryFor` forwards at each throw site; the hint text callers see is unchanged.
- **`openfda_describe_fields`** reports a missing field catalog for an accepted endpoint as `InternalError` naming the endpoint, instead of a bare `Error`.
- **Docker image** — dependencies install in a `deps` stage on the build platform (0.13.10) and musl-only packages are pruned (0.13.11). The image no longer sets `MCP_FORCE_CONSOLE_LOGGING`; base images move to `oven/bun:1.4.2`.
- **`server.json`** — npm entries take the `npx` runtime hint, and the HTTP entry fixes `MCP_TRANSPORT_TYPE` to `http` as a set value rather than a required user input.
- **npm package** excludes `dist/*.mcpb` bundles.
- **Ignore files** — `.gitignore` and `.dockerignore` cover every `.env*` file (`.env.example` stays tracked), `.dockerignore` adds the MCP registry token files, and `.mcpbignore` keeps `docs/idea.md` and `logs/` out of the bundle.
- **CodeQL workflow** runs once per language under `/language:<language>`, the category default setup uses, so its alerts close once the code is fixed.
- **Framework scripts** (`devcheck`, `lint-mcp`, `lint-packaging`, `check-skill-versions`, `release-github`) and **`framework-skills/`** resynced from mcp-ts-core 0.13.11; `scripts/install-otel.ts` and `scripts/prune-musl-packages.ts` added for the Docker build.
- **Docs** — README, `CLAUDE.md`/`AGENTS.md`, and `docs/design.md` document `openfda_dataframe_drop`, and `CLAUDE.md`/`AGENTS.md` the declared-recovery fill; the README tool and configuration reference is tightened and its header counts 15 tools.
