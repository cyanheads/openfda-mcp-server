# 0.8.1 — 2026-10-12

## Added

- **`fields`** on `openfda_lookup_ndc` and every `openfda_search_*` tool projects each inline record to the dotted paths named plus its identity key, before the page is measured; the response reports `projected_fields`. With `stage: true` only the inline page is projected, never the staged table ([#66](https://github.com/cyanheads/openfda-mcp-server/issues/66)).
- **`page_largest_fields`** names the largest fields of a single record that exceeds the inline budget on its own, and `page_bytes` now accompanies every over-budget page. Sizes are UTF-8 bytes ([#66](https://github.com/cyanheads/openfda-mcp-server/issues/66)).
- **`openfda_search_recalls` staging** adds `initial_firm_notification`, `code_info`, `more_code_info`, `center_classification_date`, `termination_date`, `address_1`, `address_2`, and `postal_code` as columns, so lot lists reach SQL (`code_info || coalesce(more_code_info, '')` is the whole list) ([#69](https://github.com/cyanheads/openfda-mcp-server/issues/69)).
- **`drug.manufacturer.registration_number`** is cataloged for `animalandveterinary/event`; it narrows an ingredient search to one approval ([#65](https://github.com/cyanheads/openfda-mcp-server/issues/65)).

## Changed

- **`sort`** accepts `asc`, `desc`, `ascending`, and `descending` in any letter case and sends lowercase `asc` or `desc`. Any other direction token is now rejected before the request; openFDA ignored it and dropped the sort key ([#64](https://github.com/cyanheads/openfda-mcp-server/issues/64)).
- **`content[]` Markdown** — table cells and SPL table cells escape characters that would change the rendering; a block marker opening a list item or an SPL caption, footer, or loose-text line is escaped; and upstream text on a heading, label, or list line is flattened to one line ([#67](https://github.com/cyanheads/openfda-mcp-server/issues/67)).
- **`content[]` header** — the `total results` line opens every search response, including no-match, with the dataset date, offset, and page size ([#68](https://github.com/cyanheads/openfda-mcp-server/issues/68)).
- **`openfda_search_animal_events`** documents that brand and manufacturer names are masked as `MSK` on every record, answers a brand or manufacturer filter that matches nothing with that guidance, and renders the drug line from the active ingredient with `brand masked: MSK` as a qualifier ([#65](https://github.com/cyanheads/openfda-mcp-server/issues/65)).
- **`openfda_dataframe_query`** rejection details describe what the read-only gate blocks: file readers, engine-setting reads, SQL run from a string, and a file named where a staged table belongs.

## Removed

- **`product_code` and `res_event_number`** staging columns of `openfda_search_recalls`; they were NULL on every row ([#69](https://github.com/cyanheads/openfda-mcp-server/issues/69)).

## Fixed

- **`openfda_describe_fields`** notes state the stored values and accepted query forms: code meanings for `reactionoutcome`, `patientsex`, `patientagegroup`, and route codes; real example values; MM/DD/YYYY `drug/shortages` dates (YYYYMMDD matches nothing); and the full `device_class` and shortage `status` sets ([#62](https://github.com/cyanheads/openfda-mcp-server/issues/62)).
- **`openfda_drug_profile` `adverse_events.total`** counts every matching report, including those with no seriousness recorded, and equals `openfda_search_adverse_events` `meta.total` for the same search ([#63](https://github.com/cyanheads/openfda-mcp-server/issues/63)). A cancellation that lands between retries now fails the call as cancelled.
- **Staged searches** report `meta.limit` as the caller's `limit`, lowered only when the byte budget dropped records, the way unstaged searches do ([#73](https://github.com/cyanheads/openfda-mcp-server/issues/73)).
