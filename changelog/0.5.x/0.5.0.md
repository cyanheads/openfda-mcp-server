# 0.5.0 — 2026-07-26

## Changed

- **DataCanvas staging is opt-in.** Every canvas-capable search tool (`openfda_search_adverse_events`, `_recalls`, `_drug_approvals`, `_device_clearances`, `_animal_events`, `_drug_shortages`, `_tobacco_reports`, `openfda_lookup_ndc`) gains a `stage` boolean input (default `false`, shared as `stageInput` in `canvas-spill.ts`). Passing `canvas_id` implies staging too. Without a staging signal, a call issues exactly one upstream request and returns one page — no canvas work at all. ([#30](https://github.com/cyanheads/openfda-mcp-server/issues/30))
- **The drain is byte-budgeted, not row-unconditional.** `spillSearch` reads a 100-row probe (`PROBE_ROWS`) to get the total and measure serialized record size, then derives a row cap and page size from a ~16 MB JSON budget (`STAGE_MAX_BYTES`), still capped by openFDA's 25,000-row `skip` ceiling (`OPENFDA_MAX_ROWS`). Record size spans three orders of magnitude across endpoints (`drug/shortages` ~1 KB vs `drug/event` ~65 KB), so a flat row cap either starved small endpoints or stalled large ones. ([#30](https://github.com/cyanheads/openfda-mcp-server/issues/30))
- **`spillSearch` no longer calls the framework's `spillover()` helper.** The character-budgeted preview (`PREVIEW_CHARS`) is gone; the drain registers directly against the canvas via `instance.registerTable()`, and the inline page is served from the drain's probe (or a direct fetch) using the caller's own `limit`/`skip` — identical to the non-staged path. ([#31](https://github.com/cyanheads/openfda-mcp-server/issues/31), [#32](https://github.com/cyanheads/openfda-mcp-server/issues/32))
- **New output field `staged_rows`**, alongside `canvas_id`/`canvas_table`/`spilled`/`truncated`, discloses how many rows actually reached the canvas versus `meta.total`.
- **`emptyResultMessage()` takes a `total` parameter.** A non-zero total settles "no match" vs "offset past the end" instead of guessing from `skip` alone.
- **New `canvasDisabledError` contract entry**, shared across the eight staging tools: requesting `stage`/`canvas_id` with `CANVAS_PROVIDER_TYPE` unset now throws a declared `canvas_disabled` `ValidationError` instead of silently ignoring the request.
- **`openfda_dataframe_query`** gains a `truncated` output field (always present) and renders a continuation hint (`ORDER BY … LIMIT … OFFSET …`) in `format()` when the canvas row cap was hit. ([#29](https://github.com/cyanheads/openfda-mcp-server/issues/29))
- **`openfda_dataframe_query`** now catches DataCanvas failures at the tool boundary and maps them onto its own contract: a new `missing_table` reason (`NotFound`) for a dropped/mistyped table, and `invalid_query` broadened to cover `non_select_statement`, `multi_statement`, `plan_operator_not_allowed`, `denied_function`, `denied_function_in_plan`, `system_catalog_access`, and `invalid_sql` (`SQL_REJECTION_DETAIL` map in `dataframe-query.tool.ts`) — recovery text now names `openfda_dataframe_describe` and corrected SQL instead of internal `registerTable()`/`drop()`/`clear()` APIs. The underlying canvas reason rides along as `data.canvas_reason`. ([#28](https://github.com/cyanheads/openfda-mcp-server/issues/28))
- **New shared helpers** in `format-utils.ts`: `canvasStagingLine()` (renders the staging disclosure whenever a call staged, independent of inline row count) and `emptyPageNote()` / `noMatchNote()` (distinguish a genuine miss from an offset past the end of a matched set, for both staged and unstaged responses).

## Fixed

- **Oversized records no longer empty the inline preview.** A single ~68 KB `drug/event` record could exceed the old 40,000-character `PREVIEW_CHARS` budget outright, so a matching query rendered `results: []` and `content[]` led with "No results found." even though hundreds of thousands of records matched. `format()`'s empty-results branch is now scoped to `meta.total === 0`. ([#31](https://github.com/cyanheads/openfda-mcp-server/issues/31))
- **`skip` addresses the same matched set in staged and unstaged modes.** Previously, with canvas enabled, `skip` indexed into the character-budgeted preview array instead of the upstream pagination offset, so the two modes disagreed about whether records existed at a given offset. `spillSearch` now serves the caller's `limit`/`skip` window directly from the upstream endpoint (via the probe page when it covers the window, or a direct fetch otherwise), matching the non-staged path exactly. ([#32](https://github.com/cyanheads/openfda-mcp-server/issues/32))
- **Staged-table retrieval hint no longer points past the table's end.** `emptyPageNote()`'s suggested follow-up query (`SELECT * FROM <table> LIMIT 10`) omits the original `skip` — the staged table starts at offset 0 and holds at most `staged_rows` records, so carrying the caller's offset into the SQL previously produced a query guaranteed to return nothing.
- **An unstaged page past the end of the matched set no longer renders as a flat no-match.** `noMatchNote()` now qualifies the miss with the request's `skip` even when canvas staging wasn't requested, so "0 results" at a high offset reads as "offset ran past the end," not "nothing matched."
- **`openfda_dataframe_query`'s 10,000-row cap is disclosed.** The framework's `truncated` flag was previously discarded; it's now carried through `structuredContent` and rendered in `content[]` with a concrete `LIMIT`/`OFFSET` continuation query. ([#29](https://github.com/cyanheads/openfda-mcp-server/issues/29))
- **Canvas SQL errors no longer leak internal API names.** `non_select_statement`, `missing_table`, and `plan_operator_not_allowed` previously escaped `openfda_dataframe_query`'s declared `invalid_query` contract with no or misleading recovery; all canvas failure reasons now resolve to a declared tool reason with recovery text scoped to actual MCP tools. ([#28](https://github.com/cyanheads/openfda-mcp-server/issues/28))
