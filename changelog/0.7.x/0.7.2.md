# 0.7.2 — 2026-08-07

## Added

- **`search` local rejection.** Every tool taking a caller-supplied `search` now rejects an unbalanced double quote, parenthesis, or range bracket, or a query ending on a backslash, before the upstream request — `assertSearchDelimitersBalanced` (`src/mcp-server/tools/schema-utils.ts`) is a three-context scanner tracking phrase/range/paren state, since a delimiter's meaning depends on which of the three it sits in. Raises the new `malformedSearchError` (`malformed_search`) reason, now declared on all ten tools that take `search`. ([#38](https://github.com/cyanheads/openfda-mcp-server/issues/38), [#43](https://github.com/cyanheads/openfda-mcp-server/issues/43))
- **`sort` grammar reaches the advertised schema.** `sort` is now built with `sortExpression()` — a comma-separated `field-path[:direction]` pattern expressed as a JSON Schema `pattern`, so the constraint is visible in `tools/list` before a client calls. Multi-field sort (`report_date:desc,status.exact:asc`) is documented as supported.

## Changed

- **`openfda_count_values` `not_aggregatable` errors now name the correction in both directions.** A count on an analyzed text field (upstream 5xx `illegal_argument_exception`) now proposes adding `.exact`; a count on a field openFDA already indexes as a keyword (404 `Nothing to count`) still proposes dropping it. Previously only the drop-suffix case was handled, so the more common miss — omitting `.exact` — fell through to the generic `query_error`. ([#40](https://github.com/cyanheads/openfda-mcp-server/issues/40))
- **`@cyanheads/mcp-ts-core`** `^0.11.0 → ^0.11.1`.
- Skills synced from framework `0.11.1`: `api-testing` gains the `createFetchMock`/`createMockSession` test fixtures and the `toolContractSuite` conformance helper; `security-pass`'s elicit-fallback guidance now requires proceeding on tool annotations (not refusing) when `ctx.elicit` is unavailable, since it is `undefined` on every Streamable HTTP request.

## Fixed

- **`openfda_drug_profile` escapes its composed Lucene queries instead of stripping quote characters.** A `drug` name ending in a backslash previously escaped the phrase's own closing quote; in the two-clause identity-resolve query this returned HTTP 200 with an unrelated 27,101-record result set instead of the intended 743, and in the five single-clause sub-queries it failed as a `token_mgr_error`. `blank_drug_name` is now tested by searchable-character content rather than by whether stripping happened to empty the string. ([#42](https://github.com/cyanheads/openfda-mcp-server/issues/42))
