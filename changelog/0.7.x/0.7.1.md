# 0.7.1 — 2026-07-27

## Fixed

- **Mirror lookups on the non-unique keys (`event_id`, `product_ndc`, `set_id`) now serve only when the value addresses exactly one record.** The gate previously served any match that fit the requested page, then ordered results by primary key; the live API orders the same non-unique match by Elasticsearch relevance, so a multi-record mirrored answer had a different `results[0]` and `content[]` rendering than the API's. A value matching two or more records now routes live at any page size. ([#37](https://github.com/cyanheads/openfda-mcp-server/issues/37))
- Of the distinct key values in the synced corpora, 98.6% of `product_ndc` (133,095 of 134,993) and 69.2% of `event_id` (3,195 of 4,618) address exactly one record and continue to serve locally; `set_id` is unaffected since no `set_id` in the mirrored `drug/label` corpus addresses more than one record in practice.
