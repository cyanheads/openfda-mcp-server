# 0.7.6 — 2026-09-21

## Added

- **`openfda_drug_profile`** accepts `drug_name` and `name` as aliases of `drug` via `inputAliases`; the advertised `inputSchema` still lists only `drug`, and an alias sent alongside `drug` is rejected ([#53](https://github.com/cyanheads/openfda-mcp-server/issues/53)).

## Changed

- **`canvas_id` inputs** on the dataframe and staging tools (`openfda_dataframe_describe`, `openfda_dataframe_query`, `openfda_search_*`, `openfda_lookup_ndc`) now use the framework's `CanvasIdSchema`, advertising the pattern `^[A-Za-z0-9_-]{10}$`. A value that can't be a canvas id fails argument validation instead of reaching the canvas lookup.
- **mcp-ts-core** `^0.13.2` → `^0.13.6`: argument rejections carry `data.reason: "invalid_arguments"` and a schema-derived recovery hint; an undeclared key that case-folds to a declared one is rewritten, and a JSON-stringified array argument is repaired; tool error `content[]` text closes with `(reason <reason>)`.
- `MCP_SESSION_MODE` README row (`stateless`, unchanged), template-synced `.env.example` and Dockerfile comments, the CodeQL-only workflow, framework skills and scripts resynced, and service-raised error reasons marked `thrownBy: 'service'` for the definition linter.

## Fixed

- **`openfda_dataframe_query`** reports a `SELECT` that prepares and then fails on a staged value (typically a `CAST` over text that doesn't convert) as `invalid_query`, carrying DuckDB's own message and a `TRY_CAST` recovery hint, instead of surfacing as an unmapped database error with no declared reason.
