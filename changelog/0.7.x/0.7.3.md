# 0.7.3 — 2026-08-07

## Fixed

- **The eight multi-row search tools bound their inline page to a 24,000-byte serialized budget.** `src/services/openfda/page-budget.ts` measures the caller's `limit`/`skip` window record by record and drops records from the tail until the array fits — never below one record, so a single oversized record is still returned whole rather than emptying the page. Every search tool discloses the cut on `page_bytes`/`page_omitted`, in `structuredContent`, `content[]`, and `enrichment.notice`, naming the continuation `skip`, a lower `limit`, `stage: true` for SQL, or `openfda_count_values` for a distribution. A page that already fits is unchanged. ([#39](https://github.com/cyanheads/openfda-mcp-server/issues/39))
- Staged searches (`canvas-spill.ts`) apply the same inline budget to their preview page, so a staged and an unstaged call never disagree about what a `limit`/`skip` window holds.
- **`openfda_get_drug_label`'s overflow notice now names a section measured to fit the budget, not the largest one on the page.** The worked re-call example is projected at the page's actual record count and quoted with its byte size, so following the notice returns what it claims; when even the always-kept metadata exceeds the budget, the notice points at `limit` instead of a section. ([#41](https://github.com/cyanheads/openfda-mcp-server/issues/41))
- **A `sections` selection that overflows the budget is disclosed, not trimmed.** `kind` stays `"full"` and every requested key is returned whole; the notice now states the selection's serialized size and that a lower `limit` or a narrower selection reduces it. ([#41](https://github.com/cyanheads/openfda-mcp-server/issues/41))
