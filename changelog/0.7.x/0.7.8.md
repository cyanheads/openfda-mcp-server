# 0.7.8 — 2026-09-22

## Fixed

- **`openfda_describe_fields`** returns `countAs` per field — the verified `openfda_count_values` expression (bare path, `path.exact`, or `null`) — instead of leaving callers to discover it by trial and error ([#49](https://github.com/cyanheads/openfda-mcp-server/issues/49)).
- **`not_aggregatable`** names the field catalog's recorded count form definitively for a cataloged field, instead of hedging a `.exact` toggle in both directions ([#49](https://github.com/cyanheads/openfda-mcp-server/issues/49)).
- **`openfda_count_values`** returns an empty tally with a notice, not `not_aggregatable`, when a countable field's search matches only records that carry no value for it ([#57](https://github.com/cyanheads/openfda-mcp-server/issues/57)).
- **`openfda_count_values`** sets `truncated` only when a look-ahead term past `limit` confirms more distinct values exist; an exact-`limit`-sized result no longer reports false truncation ([#44](https://github.com/cyanheads/openfda-mcp-server/issues/44)).
- **Every paginated search/lookup/label tool** recovers the real match total on a page requested past the end of its result set, instead of reporting `total: 0`; `meta.totalUnverified` flags the rare case where the recovery request itself fails ([#47](https://github.com/cyanheads/openfda-mcp-server/issues/47)).
