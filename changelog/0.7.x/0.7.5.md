# 0.7.5 — 2026-09-16

## Changed

- **HTTP transport declares `sessionMode: 'stateless'`** in `src/index.ts` — no tool calls `ctx.requestInput`. `MCP_SESSION_MODE` still overrides the declared default whenever it carries a meaningful value; an empty string or an unsubstituted `${…}` placeholder reads as unset. The resolved mode is now published on the server card at `/.well-known/mcp.json` under `_meta` key `io.github.cyanheads.mcp-ts-core/sessionMode`.
- **Shutdown closes any opened SQLite mirror** through the new `teardown` hook; `SIGTERM`/`SIGINT` now end the process explicitly instead of waiting for the event loop to drain.
- **`OPENFDA_API_KEY`'s `${…}`/empty-string handling moves to the framework** — `src/config/server-config.ts` drops its local `z.preprocess` guard now that `parseEnvConfig` normalizes both cases itself.
- **`@cyanheads/mcp-ts-core` `^0.12.3` → `^0.13.2`** — see Dependencies.
- **Bun engines floor raised to `>=1.4.0`**, matching the framework's own floor.

## Security

Inherited from the framework version bump — no change to this server's own source:

- The SSRF DNS guard now queries both `node:dns` resolvers, closing a Bun 1.4 Linux bypass where a name only the system resolver could see passed the guard and then connected.
- An empty rate-limit key is evicted like any other, closing a path where it was never cleaned up under distinct-key churn.
- `stripSqlComments` — run on the SQL `openfda_dataframe_query` accepts — is a linear-time scan rather than a polynomial-time regex (CodeQL `js/polynomial-redos`).

## Synced

- Framework skill tree moved from `skills/` to `framework-skills/`, so a plugin install no longer hands these development skills to the installing agent; adds the `release-pr-review` skill and resyncs `CLAUDE.md`/`AGENTS.md`, framework-shipped `scripts/`, and `changelog/template.md`.
- README restructured around an Overview opener and a per-tool `<sub>tool</sub>` capability reference; `.claude-plugin/plugin.json` and `.codex-plugin/mcp.json` wire `OPENFDA_API_KEY` through `lint:packaging`'s new `userConfig`/`env_vars` checks; GitHub issue forms gain a security-advisory link and secondary-label guidance.
