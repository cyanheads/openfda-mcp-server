# 0.6.0 — 2026-07-26

## Added

- **`openfda_get_drug_label` gains a `sections` input** (string array). Passing section names (e.g. `["boxed_warning","indications_and_usage"]`) projects each record to those keys plus always-kept metadata (`openfda`, `set_id`, `id`, `effective_time`, `version`) and returns `kind: "full"` regardless of size. A name no record on the page carries is reported on `enrichment.notice`; the page's available names are listed only when nothing matched at all, since a typo and a genuinely absent section otherwise produce the same metadata-only record. ([#11](https://github.com/cyanheads/openfda-mcp-server/issues/11))
- **New output field `kind: "full" | "outline"`** on `openfda_get_drug_label`, plus `outline[]` (section name + serialized byte size, largest first) when `kind` is `"outline"`. ([#11](https://github.com/cyanheads/openfda-mcp-server/issues/11))
- **`OPENFDA_MAX_SKIP` and `assertSkipWithinCeiling()`** (`schema-utils.ts`) — the shared pagination-ceiling constant and handler guard every paginated tool now calls before spending an upstream request. ([#27](https://github.com/cyanheads/openfda-mcp-server/issues/27))
- **`AGGREGATE_ROUTE`** (`canvas-spill.ts`) — the recovery clause appended wherever truncated staging discloses a cut, pointing at `openfda_count_values` for a whole-match distribution instead of a `GROUP BY` over the staged slice. ([#36](https://github.com/cyanheads/openfda-mcp-server/issues/36))
- **`formatCell()`** (`format-utils.ts`) — JSON-stringifies nested structures for `openfda_dataframe_query`'s rendered table instead of collapsing them to `[object Object]`.
- **`tests/mcp-server/tools/definitions/pagination-contract.test.ts`** and **`record-parity.test.ts`** — cross-tool suites exercising the pagination contract and content[]/structuredContent parity at the tool boundary, where the definition linter's `format-parity` sentinel can't see past a dynamic-record's `z.record()` shape.

## Changed

- **`openfda_get_drug_label`'s default response shape changes for oversized labels.** A single SPL record can run to tens of thousands of tokens (a warfarin label is ~130 KB across 36 top-level keys); a page that clears the framework's `outlineOnOverflow` (`@cyanheads/mcp-ts-core/utils`) 24,000-byte budget now returns `kind: "outline"` instead of the full record, with re-call guidance naming the three largest sections. A page under budget still returns `kind: "full"`, unchanged. This is the breaking change: previously any matching query returned the complete label regardless of size. ([#11](https://github.com/cyanheads/openfda-mcp-server/issues/11))
- **`skip` is no longer capped at the schema level** on every paginated tool (`search_adverse_events`, `_recalls`, `_device_clearances`, `_drug_approvals`, `_drug_shortages`, `_animal_events`, `_tobacco_reports`, `lookup_ndc`, `get_drug_label`). Previously a `.max(25000)` rejected an over-ceiling `skip` as a generic `ValidationError` before the handler ran, so the declared `pagination_limit_reached` reason and its recovery hint were unreachable. Handlers now call `assertSkipWithinCeiling()` first and raise the typed reason themselves. `openfda_count_values` has no `skip` input and drops the reason it could never reach. ([#27](https://github.com/cyanheads/openfda-mcp-server/issues/27))
- **Dynamic-record renderers now route every field into `content[]`.** Several `rendered`/allowlist sets over-claimed fields their curated summary lines only partially or conditionally emit: `brand_name`/`generic_name` behind an entry-0 lookup (drug approvals, adverse events), `advisory_committee` and `decision_code` never rendered (device clearances), product-problem placeholders filtered out and zero counts treated as absent (tobacco reports), and several nested arrays (device narratives, drug/reaction/animal sub-records, NDC packaging) rendered only a partial subset. Each now spreads the full value through `formatRemainingFields`, so `content[]` matches `structuredContent`. ([#24](https://github.com/cyanheads/openfda-mcp-server/issues/24))
- **A truncated canvas stage now names `openfda_count_values`** in its disclosure text (`stagingNotice()`, `canvasStagingLine()`) and in the `stage` input description — a `GROUP BY` over a partially-staged table describes only the staged rows, not the whole matched set. ([#36](https://github.com/cyanheads/openfda-mcp-server/issues/36))

## Fixed

- **`openfda_search_adverse_events` misrouted device reports through the drug renderer.** A `device/event` record also carries its own `patient` array, so the drug branch — checked first — intercepted every device report before the device branch could run. Device records are now checked first. ([#24](https://github.com/cyanheads/openfda-mcp-server/issues/24))
- **`openfda_dataframe_query`'s rendered table now unions headers across all returned rows** instead of taking them from row 0 — a `SELECT` over sparse staged records can omit a column from the first row that a later row carries, which previously dropped that column from `content[]` entirely.
